- 최초 열기의 중복 SDK 해석을 제거했습니다. 상속 텍스처 UV를 얻으려고 같은 SKP 전체를 다시 읽던 처리를 없앴습니다. 첫 열기·재열기 모두 SDK 모델 하나만 사용합니다.
- 이미 읽은 면에 유효 재질을 잠시 바인딩해 SDK UVHelper로 좌표를 얻고 즉시 원래 면 재질로 복구합니다. 정상/오류/예외 종료 시 모두 복구 범위를 벗어나도록 관리합니다. 수정 중에는 UI 진행 콜백을 호출하지 않습니다.
- 1.21의 디스크 UV 캐시와 원본 해시 사전 읽기도 실행 경로에서 제거했습니다. 기존 캐시가 없어도 적용되며, 캐시 유무에 따른 로딩 분기가 없습니다. 과거 캐시 파일은 참조하지 않습니다.
- 텍스처 무손실 압축은 독립 이미지 단위로 제한된 CPU 작업에서 처리합니다. SDK·OpenGL 호출은 기존 소유 스레드에서 유지합니다. 이미 압축된 이미지는 건너뛰며, 최대 4개 작업·작업 중 원본 크기 합 64MB를 기준으로 제한합니다. 이보다 큰 단일 이미지는 단독 처리합니다.
- 280MB 원본 숙소 파일 실제 첫 열기: 1.21 기준 63.04초 → 이번 검사 39.87초. PC/드라이버/동시 작업에 따라 달라집니다. 원본 SDK 파일 해석·형상·텍스처 추출 비용은 여전히 존재합니다.
- 같은 숙소 파일에서 SDK 읽기 비교: 기존 이중 해석 49.24초 → 단일 해석 34.50초. SDK 파싱 호출 2회 → 1회를 직접 검사했습니다.
- 상속 UV 1,318,056개를 포함한 전체 정점 위치·UV·면 방향·재질 색상·텍스처 RGBA 결과가 기존 방식과 일치합니다. 1,263,806개 원본 면의 재질·UV 배치 상태도 같습니다.
- 원본을 SDK로 저장한 뒤 읽으면 기존 코드에서도 검증값이 달라지는 현상이 있어, 기존 코드로 저장한 대조 파일과 수정 코드로 저장한 파일을 재열기해 비교했습니다. 두 저장 파일의 결과와 원본 면 상태가 동일합니다.
- Koki 원본도 기존 28.01초 → 단일 해석 22.01초를 확인했고 결과 검증값이 일치합니다.
- 텍스처 압축 비교: 3.77초 → 2.46초. 복원 RGBA와 압축 후 메모리 절감량 630,815,204바이트가 같습니다.
