# ToothFairy_Viewer 1.00 — GitHub 연결본

업데이트 주소를 실행 파일에 내장했습니다: https://raw.githubusercontent.com/leejg04133-create/ToothFairy_Viewer/main/latest.json
실제 서버의 1.00 정보 확인을 검증했습니다. 이번에 변경된 EXE와 latest.json은 GitHub Desktop에서 Commit → Push origin해야 온라인에도 반영됩니다.

## 현재 파일

- `1.00/SkpViewportViewer.exe`: 실행 파일. EXE 내부 제품 버전도 1.00입니다.
- `1.00/notes.txt`: 변경 내역.
- `latest.json`: 버전, 상대 다운로드 경로, 파일 크기, SHA-256, 변경 내역. 배포 준비 스크립트가 생성합니다.

실행 파일은 기존 R6처럼 설치된 호환 SketchUp을 자동으로 찾습니다. SDK DLL을 AppData에 추출하지 않습니다. 업데이트 기능 자체도 서버 주소가 비어 있을 때는 인터넷 요청을 하지 않습니다.

## 최초 연결본 게시

1. GitHub Desktop에서 `ToothFairy_Viewer` 저장소를 선택합니다.
2. 변경된 파일들을 `1.00 업데이트 서버 연결`이라는 메시지로 Commit to main합니다.
3. 상단 Push origin을 누릅니다. GitHub Pages 설정은 필요하지 않습니다.
4. `1.00/SkpViewportViewer.exe`를 사용자에게 전달합니다. 연결 전 EXE는 스스로 원격 주소를 알 수 없으므로 이번 한 번은 교체해야 합니다.

사용자에게 GitHub 로그인이나 토큰을 요구하지 않습니다. 공개 파일 다운로드와 유료 제품 인증은 별도입니다.

## 이후 1.01 배포

1. 코드의 버전과 Windows 제품 버전을 함께 1.01로 올리고 해당 버전으로 빌드합니다.
2. `tools/prepare_viewer_release.ps1 -Version 1.01 -ExePath 실제빌드경로 -Notes '변경 내역'`으로 배포 파일을 준비합니다. EXE 내부 버전이 다르면 스크립트가 중단합니다.
3. 생성된 1.01 폴더와 latest.json을 이 저장소로 복사한 뒤 GitHub Desktop에서 Commit → Push origin합니다.
4. 다음 실행 또는 설정에서 수동 확인할 때 새 버전 알림이 표시됩니다. 같은 버전 파일을 덮어써 재배포하지 말고 버전을 올립니다.

## 사용자 화면과 적용 방식

설정 상단에 현재 버전이 고정됩니다. 새 버전 확인 시 설정 아이콘 테두리/알림 점이 0.7초 간격으로 깜빡입니다. 최신/연결 전/확인 실패에서는 깜빡이지 않습니다. 설정 아이콘을 하단 메뉴로 옮겨도 알림이 표시됩니다.

새 버전 버튼 → 변경 내역 확인 → 다운로드 → 크기/SHA-256 확인 → 다시 시작 순서입니다. 모델 편집 중이면 먼저 저장하도록 안내하고 자동 종료하지 않습니다. 파일 이름을 바꿔 사용해도 현재 실행 파일 이름을 유지하여 교체합니다. 다시 시작할 때 열려 있던 모델 경로를 넘깁니다.

업데이트 시 현재 EXE 옆에 `.update-new`, `.update-helper.exe`, `.previous`가 사용됩니다. `.previous`는 이전 EXE 백업입니다. 실행 파일 폴더에 쓰기 권한이 없으면 현재 버전을 유지하고 실패를 표시합니다. 관리자 권한을 자동 요청하지 않습니다. 교체/실행 실패 복구와 테스터 PC별 실제 실행은 구분해야 하며, 모든 PC에서 성공했다고 보장하지 않습니다.

## 확인한 범위

로컬 테스트에서 버전 비교, 같은/낮은 버전 차단, 잘못된 상대 경로 차단, 손상된 다운로드 거부, 정상 다운로드 검증, 실행 중인 테스트 EXE 종료 후 교체와 재실행을 검사했습니다. 실제 GitHub 서버의 버전 정보도 뷰어와 동일한 WinHTTP 코드로 확인했습니다. 온라인에서 더 높은 버전으로 전체 교체하는 과정은 향후 버전 게시 후 검증 대상입니다.
